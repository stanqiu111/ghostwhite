How ÉTHÉRÉ is distributed

No one runs ÉTHÉRÉ.
Every node does.

There is no central database and no company in the middle. Each server — a node — keeps its own authors and posts, and nodes trade activity with each other by posting JSON to one another's inboxes.

What a node owns

Ownership is the whole idea. Nothing about an author is stored centrally, so there is nothing central to fail or to take down.

Its authors

Every account belongs to exactly one node. An author's id is a full URL on that node, like …/api/authors/<uuid>, so the id itself says where they live.

Its posts

Entries are written to the author's own node first. Peers receive copies, but the home node stays the source of truth for edits and deletions.

Its inbox

Each author has an inbox at /api/authors/<id>/inbox. It is the only door other nodes knock on, which keeps the protocol small.

On the wire

When you publish to someone who follows you from another node, this is the request your node sends theirs.

Example requestthis node → peer
POST /api/authors/7f3c…e21a/inbox1
Host: peer-node.example
Authorization: Basic <node credentials>2
Content-Type: application/json

{
  "type": "entry",3
  "id": "{{ local_host }}/api/authors/…/entries/…",
  "title": "Shipped the bullet curtain",
  "contentType": "text/markdown",
  "content": "Comments now scroll across the stream…",
  "author": { "id": "{{ local_host }}/api/authors/…", … },
  "published": "2026-10-02T14:20:00+00:00",
  "visibility": "PUBLIC"4
}
  1. One endpoint. The request targets the recipient's inbox on their node, addressed by the author's id.
  2. Node-to-node credentials. Your node authenticates as itself with HTTP Basic, not as you. This node only accepts requests from nodes it holds credentials for.
  3. A typed activity. The type field tells the receiver which of five handlers to run.
  4. Visibility travels with it. The receiving node is told who the post is for, and is only sent posts its authors are allowed to see in the first place.

Five things cross the wire

Everything nodes say to each other is one of these. An unknown type is rejected with a 400.

entry

A new or edited post, or a deletion of one.

follow

A follow request, and later its acceptance or refusal.

like

A like on an entry or comment, so counts match across nodes.

comment

A reply, sent to the entry's author and anyone else who can see it.

author

A profile update, so mirrored copies stay current.

Trust between nodes

Federation only works if a node can decide who it talks to.

Credentials per peer

Each connection is a pair of HTTP Basic credentials agreed between two admins. A request without valid ones is refused before it reaches any handler.

A peer can be cut off

Disabling a node stops this node sending to it and refuses anything it sends back, without deleting the authors or posts already received.

Failure stays local

Deliveries time out after 10 seconds. A slow or offline peer does not stall your own feed, because your node already holds everything it serves.
